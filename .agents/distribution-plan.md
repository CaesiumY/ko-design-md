# 배포·유입 채널 계획

**작성:** 2026-08-24 · **근거 스킬:** `marketing-skills:directory-submissions`
**전제 문서:** [`product-marketing.md`](./product-marketing.md)

> **이 계획의 전제 하나.** 참조한 스킬은 유료 SaaS를 기준으로 쓰여 있다(G2 리뷰,
> 가격 페이지, 무료체험 전환). 이 프로젝트는 **수익화하지 않는 OSS 카탈로그**라
> 티어의 절반이 해당 없음이다. 스킬 자신의 triage 규칙 — "제품이 진짜로 맞는
> 곳에만 등재하라. 억지로 넣으면 모더레이터가 거절하고 first-submission 이점만
> 태운다" — 을 따라 **적용/비적용을 명시적으로 갈랐다.** 비적용을 억지로 채우지 말 것.

## Phase 0 — 준비 상태 실측

스킬의 9개 체크 항목을 이 레포에 대해 실제로 확인한 결과다.

| # | 항목 | 상태 | 근거 |
|---|------|------|------|
| 1 | 공개 접근 가능 | ✅ | getdesign.kr, 로그인 없음 |
| 2 | 가격 페이지 | ➖ 해당 없음 | 무료 OSS. 등재 폼이 요구하면 "Free / MIT+CC BY" 로 답한다 |
| 3 | 개인정보처리방침·약관 | ⚠️ **없음** | 사이트에 라우트 없음. `@vercel/analytics`가 도는 중이라 등재 폼에서 요구받을 수 있다 |
| 4 | 로고 자산 | 🔶 부분 | `favicon.svg`·`favicon.ico`·`apple-touch-icon.png`(180×180) 있음. **1024×1024 정사각 PNG 없음** — 다수 디렉터리 필수 |

#3·#4·#5는 등재 폼을 채우다 막히는 실무 마찰이라 반나절이면 해소된다.

## 한국 채널 — 스킬에 없는 부분

참조 스킬은 영미권 채널만 다룬다. PRD의 성공 지표가 "한국 dev Twitter/블로그/뉴스레터
자발 언급 2~3건"이므로 **여기가 실제 무게중심이다.**

| 채널 | 성격 | 접근 |
|------|------|------|
| GeekNews (news.hada.io) | 개발자 큐레이션. 국내 Show HN에 가장 가까움 | 직접 제출. 기술적 각으로 |
| 요즘IT / 커리어리 | 디자이너·개발자 아티클 | 기고 또는 자연 공유 |
| 디스콰이엇 | 메이커 커뮤니티 | 빌드 로그 형식 |
| 국내 dev/디자인 뉴스레터 | 주간 큐레이션 | 제보 폼 |
| GitHub Topics | `design-system` · `korean` · `llm` · `design-tokens` | 저장소 topic 설정 |

**공통 원칙:** 스킬의 Reddit 90/10 규칙이 국내 커뮤니티에도 그대로 적용된다.
그리고 **자랑이 아니라 숫자와 배운 것**이 통한다 — 이 프로젝트에는 실제로 할 얘기가
있다(인용 무결성을 CI로 강제한 방법, OKLCH 드리프트 게이트, 프리뷰 반응형 휴리스틱).

## 실행 순서

**지금 막힌 것부터.**

1. **목적지 페이지 (하드 블로커 해소)** — 등재보다 먼저.
   - ~~카테고리 페이지 `/categories/{category}`~~ — **한 번 만들었다가 되돌렸다
     (2026-08-25).** 근거가 약했다. "한국 커머스 디자인 시스템 같은 검색어가 착지할
     페이지가 없다"는 Search Console 데이터가 아니라 이 문서의 추정이었고, 실제
     분포를 세어 보니 11개 카테고리 중 7개가 항목 1개뿐이라 전부 인덱싱하면 얇은
     페이지가 사이트 전반의 품질 신호를 깎는다. 임계값(항목 2개 이상)으로 4개만
     남기면 각 페이지가 2~3개를 나열할 뿐이라 개별 항목 페이지 대비 더해 주는
     정보가 얇고, 그 임계값을 head·breadcrumb·sitemap·링크 네 곳이 일관되게
     따라야 해서 결합 비용이 컸다(약 315줄 · 7파일, 빈 카테고리 200 버그 1건 발생).
     **다시 검토할 조건:** 카탈로그가 커져 여러 카테고리가 자연히 5개 이상이 되거나,
     Search Console에 카테고리 단위 쿼리가 실제로 잡힐 때. 그때는 임계값 장치 자체가
     필요 없을 수 있다.
   - `/about` 또는 확장된 홈 하단: 무엇인지·왜 믿을 만한지(인용·CI 게이트)·어떻게 쓰는지.
2. **자산 정비 (반나절)** — 1024×1024 PNG, 스크린샷 5~8장, 개인정보 처리 고지.
3. **AI/에이전트 표면** — 이미 있는 skills.sh·플러그인 마켓플레이스 등재를 정본으로
   두고, MCP 레지스트리는 PRD V1.x에서 MCP 서버가 나온 뒤에.
4. **런칭** — GeekNews + Show HN 동시가 아니라 **국내 먼저**. 국내 반응이 영문
   포스팅의 근거("한국 개발자 커뮤니티에서 N")가 된다.
5. **리스티클·버티컬** — 롤링.

## 측정 — 여기서 막힌다

스킬의 KPI 표는 DR·referring domains·signups를 본다. 이 프로젝트의 등가물은
PRD가 정한 주간 순방문 500+ / Copy 1,000+월 / star 100+ / 자발 언급 2~3건이다.

**계측 배선은 2026-08-25에 끝났다** — `design_md_copy`(primary metric, design.md
두 표면 전용)와 `asset_copy`(토큰·스와치·스킬 설치)로 이름을 갈라 발행한다. 다만
**값은 아직 쌓이는 중이라 채널별 기여를 판정할 수 있는 시점이 아니다.** 등재를
시작하기 전에 최소 몇 주의 baseline 을 확보할 것 — baseline 없이 등재하면 유입이
늘어도 그게 등재 덕인지 알 수 없다.

- 남은 것: referrer 기록으로 채널별 기여 분리
- star·자발 언급은 여전히 수동 확인
