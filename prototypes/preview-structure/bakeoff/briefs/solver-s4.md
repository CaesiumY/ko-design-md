# 문제 4 를 푸는 쪽에 더하는 지시

공통 지시(`solver-common.md`)를 먼저 읽는다. 이 파일은 문제 4(라프텔 프리뷰를 처음부터 쓰기)에만 더하는 것이다.
공통 지시와 부딪치면 이 파일을 따른다.

## 1. 준비

1. 가지를 친다(가지 이름은 너를 부른 글에 있다): `git switch -c eval/{구조}-s4{a 또는 b} {끝}`
2. `pnpm install`, 그리고 공통 지시 1절 4번의 확인.
3. **열어 보지 않고** 라프텔의 기존 프리뷰를 지운다: `git rm -q public/preview/laftel/preview.html`.
   이 삭제만 담아 커밋한다(**준비 커밋**). 줄 수는 준비 커밋부터 센다: `git diff --stat <준비 커밋> <풀이 커밋>`.

## 2. 보지 않는 것 (공통 지시에 더해)

라프텔의 기존 프리뷰를 어떤 길로도 보지 않는다.

- git 이력, 다른 브랜치, `git show`, `git stash`, 배포된 사이트.
- 저장소 안에서 라프텔 프리뷰의 선택자, 색, 글을 담고 있는 자료(대비 기준선, 대비 분류표, E2E 스냅샷, OG 이미지 생성물)의 라프텔 부분.
- 같은 문제를 푸는 다른 에이전트의 가지.

봐도 되는 것: `services/laftel.md`, `services/laftel.tokens.json`, 치지직과 토스의 원본과 프리뷰, `STANDARD.md`, 구조 안내.

## 3. 범위와 확인

- 범위는 SCENARIOS.md 의 문제 4 가 정한 그대로다. 더 만들지 않는다.
- 확인은 슬러그 단위만 돌린다: 구조 안내가 말하는 약속 검사(라프텔에 대해)와 `pnpm validate:previews --slug laftel --verbose`.
  `pnpm gates` 와 `pnpm test` 전체는 돌리지 않는다. 구조 안내가 새 항목을 더할 때 돌리라고 한 것은 돌린다.
- 검증기가 막으면 메시지를 따라 고친다. 통과하려고 md 에 없는 값을 지어내지 않는다.

## 4. 결과 파일에 더 적는 것

경로는 `prototypes/preview-structure/results/{구조}-s4{a 또는 b}.md`.

- 새로 만든 파일의 목록과 줄 수(손으로 쓴 것과 명령이 만든 것을 나눠서).
- 확인을 돌린 회차마다: 어느 검사가 무엇을 막았는지 한 줄, 그 막힘의 종류(구조, 안내, 환경, 내 실수, 그리고 **md 해석**: 구조와 무관하게 DESIGN.md 를 화면으로 옮기다 생긴 것).
- 처음으로 두 검사가 모두 통과한 회차.
- 안내에서 답을 찾지 못해 치지직이나 토스의 원본을 보고 따라 한 곳.
