# 치지직 공통 바탕 메모

> PROTOTYPE. `public/preview/chzzk/preview.html` 을 `STANDARD.md` 대로 옮기며 내린 판단을 적는다.
> md 줄 번호는 `services/chzzk.md`, 프리뷰 줄 번호는 옮긴 뒤의 `public/preview/chzzk/preview.html` 기준이다.

## 한눈에

- 줄 수는 733줄에서 869줄이 됐다. 틀 블록 74줄을 붙였고, 칸마다 시연 자리 한 겹이 더해졌다.
- 구역은 히어로, 화면(3칸), 버튼(1칸), 입력(3칸), 내비게이션(2칸), 콘텐츠(4칸), 피드백(1칸)이다. 선택과 브랜드 고유는 만들지 않았다.
- 지운 글은 섹션 번호 다섯(`01`~`05`)과 옛 섹션 제목 셋(탐색과 입력, 라이브 카드와 배지, 채팅과 모달)뿐이다.
  옛 제목 "버튼", "화면"은 구역 제목과 글자가 같아 그대로 남는다. 라이트와 다크에서 보이는 글을 옮기기 전과 다중집합으로 대조했다.

판단이 갈릴 수 있는 곳은 넷이다. 그중 정렬 메뉴는 기준의 글자와 다르게 둔 유일한 칸이라 결정이 필요하다.

- **맨 위 덩어리를 화면으로 올렸다.** 기준 1절은 히어로에 브랜드 이름, 슬로건, 주요 버튼, 로고만 두게 하고, ADR 0015 는 히어로에만 있던 화면을 옮기라고 한다.
  사이트 머리와 사이드바, 추천 라이브 격자는 홈 화면 한 장이므로 하나의 화면 재현으로 묶었다. 그 안에 있던 더미 데이터 표기 둘은 `.pv-screen` 밖 이름표 아래로 뺐다.
  `<header class="hdr">` 는 `<div>` 로, `<main class="main">` 과 `<section class="sec">` 도 `<div>` 로, `h2.sec-h` 는 `h3` 으로 바꿨다. 문서에 `<main>` 과 `<header>` 가 하나씩이고 `<section>` 과 `<h2>` 는 구역에만 있다.
- **채팅 입력을 브랜드 고유가 아니라 입력에 뒀다.** 쓰임이 "값을 써넣는 칸"이고 md 의 컴포넌트 이름도 `chat-input`(md 325~327)이다. 채팅은 여러 브랜드가 함께 쓰는 컴포넌트이기도 하다.
  칸 안에는 메시지 목록이 든 채팅 패널도 있는데, 칸의 주된 일이 입력창과 그 상태라 칸을 쪼개지 않았다.
- **정렬 메뉴를 내비게이션이 아니라 입력에 뒀다. 아직 정해지지 않은 판단이다.** 이름은 메뉴지만 쓰임은 "목록을 열어 값(정렬 기준)을 골라 넣는 칸"이다. 닫힌 모습(인기순 버튼)과 열린 모습(목록)이 한 칸에 나란히 있다.
  기준의 예시 목록은 메뉴를 내비게이션에 적어 두었고 이 칸의 이름표도 "메뉴"라고 부른다. 글자대로 읽으면 이 칸은 내비게이션이고, 그러면 입력 2칸, 내비게이션 3칸이 된다. 칸 하나를 옮기는 일이다.
- **채널 머리와 구독 티어 배지를 콘텐츠에 뒀다.** 옛 자리는 화면 섹션이었지만 화면 한 장이 아니라 채널 정보 묶음과 배지 견본이다. 쓰임이 "내용을 담아 보여 주는 것"이다.

## 만들지 않은 구역

- **선택(`selection`)**: md 에 체크박스, 라디오, 스위치, 세그먼트 컴포넌트가 없다. 필터 칩은 모양만 언급된다("알약", md 275, 339). 색, 크기, 선택 상태 값이 없고 옛 프리뷰도 칩을 화면 재현 안에서만 그렸다. 칸을 새로 지어내지 않았다.
- **브랜드 고유(`brand`)**: 기준이 바뀌어 채팅 입력이 입력 구역으로 가면서 남는 칸이 없다. 닉네임 색 20종과 역할색은 md 가 토큰으로 옮기지 않았다(md 361).

## 넣은 손끝 반응과 md 근거

| 반응 | 프리뷰 선택자 | md 근거 |
| --- | --- | --- |
| primary, secondary 버튼 hover, 오버레이 5% 를 배경 이미지로 얹음 | `.btn-1:hover`, `.btn-2:hover` | 240(두 갈래 토큰, solid 는 배경 이미지), 307, 337 |
| outlined 버튼 hover, 배경색 자체가 lighten 5% | `.btn-out:hover` | 240 |
| 사이드바 항목 hover, 배경색 흰색 5%(라이트 검정 5%) | `.side-i:hover` | 287, 240 |
| 검색창 초점, 테두리와 캐럿 색 | `.field.fld-live:focus-within`(원래 있었음) | 291 |
| 썸네일 hover, 검정 50% 덧씌움 0.2초 | `.thumb:hover::before`(원래 있었음) | 271, 323 |
| 채팅 입력 초점, 오버레이 | `.chat-live:focus-within`(새 "직접 입력" 줄) | 358 |
| 헤더 전환 `transform .2s ease-in-out` | `.hdr` 의 `transition` | 283 |

- hover 규칙은 `.is-sel` 규칙보다 앞에 뒀다. 나란히 그린 selected 견본은 마우스를 올려도 12% 그대로다(실측).
- **눌림(`:active`)은 하나도 넣지 않았다.** md 는 hover 5% 와 selected 12% 만 규정하고(240, 337) 눌림은 말하지 않는다. selected 를 눌림으로 읽지 않았다.
- tertiary, danger, 아이콘 전용 버튼, 상단 탭, 태그 칩, 팝오버 항목, 모달에는 md 가 정한 반응이 없어 넣지 않았다.
- 채팅 입력의 "활성, 2px 테두리"는 md 가 "활성 클래스가 붙으면"이라고만 적어(358) 어떤 조작으로 켜지는지 알 수 없다. 나란히 그린 견본만 두었다.
- 헤더의 전환은 md 가 값만 적고 무엇이 움직이는지는 적지 않아 선언만 있고 눈에 보이는 변화는 없다.
- 썸네일 덧씌움의 곡선 `cubic-bezier(.65, 0, .35, 1)` 은 옛 프리뷰에 있던 값이다. md 본문은 0.2초만 적는다. 건드리지 않았다.
- 새로 `<button>` 이 된 필터 칩과 탭에는 초점 스타일을 쓰지 않았다. 브라우저 기본 초점 테두리가 보인다.

| 상단 탭 넷(게임, e스포츠, 스포츠, 엔터+) | 내비게이션 `top-tabs` 칸의 새 "직접 선택" 줄(프리뷰 751) | `data-pv-toggle="aria-selected"`, `role="tablist"` 와 `role="tab"` | 257(상단 탭 링크 17px/21px 800). 현재와 비활성 색은 옛 견본 값 그대로다 |

- 선택지는 진짜 `<button type="button">` 으로 그렸고 스타일은 속성 값(`[aria-pressed="true"]`, `[aria-selected="true"]`)으로 건다.
- 나란히 그린 "현재", "비활성" 견본과 모바일 재현 안의 칩은 그대로 뒀다. 모바일 재현은 `role="img"` 라서 그 안에 누르는 요소를 두지 않았다.
- 선택된 칩의 글자색은 다크 시트의 델타 규칙이었는데, 속성으로도 걸리도록 토큰(`--chip-on-ink`)으로 바꾸고 델타 규칙을 지웠다. 모바일 재현의 `.m-dark .tab.is-on` 규칙도 같은 토큰 재정의로 바꿨다. 보이는 색은 같다.

## 기준과 틀에서 모호하거나 모자랐던 곳

### 고쳐야 하는 것 (`frame.css`)

1. **`.pv-stage--stack` 이 `flex-wrap: wrap` 을 물려받는다.** 세로로 쌓인 시연에서 브라우저가 자식의 높이를 "늘어나기 전 폭"으로 재고 그 뒤에 폭만 늘린다.
   그래서 16:9 썸네일이나 플레이어처럼 폭이 넓어지면 키도 커지는 내용이 칸 밖으로 넘쳐 아래 칸과 겹친다. 976 폭에서 라이브 시청 화면 칸이 내용 609px 에 상자 523px 였다.
   가로 넘침 검사로는 안 잡힌다. `.pv-stage--stack` 에 `flex-wrap: nowrap` 한 줄이면 해결된다.
2. **`.pv-screen` 에 폭이 없다.** 가로 시연 자리에서는 내용 폭으로 쪼그라들고, 세로 시연 자리에서는 위 1번 때문에 높이가 어긋난다. `width: 100%` 가 필요하다.
3. 위 둘을 틀을 건드리지 않고 막느라 브랜드 쪽에 규칙 셋을 뒀다(프리뷰 295~296, 360).
   시연 자리의 직계 자식 class 열하나에 `width: 100%`, 화면 재현 틀 둘에 `width: 100vw; max-width: 100%`, 휴대폰 틀에 `width: 390px; max-width: 100%`.
   **틀이 고쳐지면 앞의 두 규칙은 지워야 한다.** `.pv-*` 선택자에는 선언을 더하지 않았다.
4. **`.pv-hero` 규칙이 없다.** 히어로 안쪽 여백을 브랜드 쪽 감싸개(`.hero-wrap`)가 정하는데, 구역과 좌우를 맞추려면 틀의 여백(24px, 16px)과 접히는 폭(767px)을 브랜드가 따라 써야 한다. 틀이 여백을 변수로 내주거나 `.pv-hero` 에 여백을 주면 좋다.
5. **구역 제목의 굵기 700 과 자간 0 이 틀에 박혀 있다.** 치지직의 장식 서체 Nemony 는 400 한 굵기뿐이고(md 257, 259) Pretendard 단계는 자간이 -0.3px 이다. 서체와 색은 브랜드 것이라는 약속이 굵기와 자간에는 닿지 않는다.
   지금은 Nemony 가 로드되지 않아 Pretendard 700 으로 보인다.
6. 접히는 폭이 900px 에서 767px 로 내려가 768 폭에서 칸이 두 열이 된다(시연 자리 약 310px). 치지직은 삐져나오지 않았지만 다른 항목은 여기서 터질 수 있다.

### 정해 주면 좋은 것 (`STANDARD.md`)

1. **칸 안에서 더미 데이터 표기의 자리.** "이름표 쪽"이라고만 돼 있다. 이름표(와 다크 변형 `<template>`) 바로 뒤, 시연 자리 앞에 뒀다. 그래서 칸의 자식은 이름표, (다크 변형), (더미 데이터 표기), 시연 자리다.
2. **스펙 줄과 조작 안내의 자리.** 상태 이름표처럼 시연 자리 안, 시연 뒤에 뒀다. 화면 칸에서는 `.pv-screen` 밖이다.
3. **`.pv-screen` 안에 `data-pv-toggle` 을 둘 수 있는가.** 기준은 `pv-` class 와 구역만 금한다. 홈 화면의 필터 칩에 썼다.
4. **md 가 selected 는 규정하고 눌림은 규정하지 않을 때.** 넣지 않았다. 이런 항목이 더 있을 것이다.
5. **한 칸이 두 쓰임을 함께 그릴 때 쪼갤지.** 채팅 칸(패널과 입력창)과 채널 머리 칸(정보 묶음과 배지)은 쪼개지 않고 주된 쓰임의 구역에 뒀다.
6. **칸의 크기.** 버튼은 변형 다섯을 한 칸에 둔 옛 구성을 그대로 옮겼다. 기준의 예시(`button-primary`)처럼 변형마다 칸을 나누려면 "button, 변형과 상태" 이름표와 변형 공통 스펙 줄의 자리를 새로 정해야 한다.
7. **화면 재현이 `role="img"` 일 때.** 그 안의 요소는 보조 기술에 가려지므로 누르는 요소를 둘 수 없다. 홈 화면 재현에는 `role="img"` 를 달지 않았고 나머지 둘에는 옛 것이 남아 있다.

### 다른 곳에 미치는 것

- **검사기의 전제.** `src/lib/preview-validator.ts` 242~249 는 프리뷰에 뿌리 감싸개가 없다고 전제한다(정부 식별 표기 규칙). `main.pv-page` 가 바로 그 감싸개다. 치지직에는 영향이 없지만 KRDS 를 옮길 때 이 규칙이 무뎌진다.
- **대비 총계가 움직인다.** 로컬 측정으로 텍스트 요소는 테마마다 300에서 327, 텍스트 미달은 라이트 17에서 25, 다크 10에서 12 다.
  늘어난 미달은 틀이 아니라 브랜드 색이다. md 대로 넣은 hover 가 hover 측정에 새로 잡혔고(흰 글자와 브랜드 면은 평소에도 미달이다), 새 줄의 "전송"과 비활성 탭이 기존 미달과 같은 색이다.
