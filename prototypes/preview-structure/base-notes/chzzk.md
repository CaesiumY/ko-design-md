# 치지직 공통 바탕 메모

> PROTOTYPE. `public/preview/chzzk/preview.html` 을 `STANDARD.md` 대로 옮기며 내린 판단을 적는다.
> md 줄 번호는 `services/chzzk.md` 기준이다. 치지직은 손으로 옮겼다(변환 스크립트 없음).

## 한눈에

- 줄 수는 733줄에서 874줄이 됐다. 틀 블록을 붙였고, 칸마다 시연 자리 한 겹이 더해졌다.
- 구역은 히어로, 화면(3칸), 버튼(1칸), 입력(3칸), 내비게이션(2칸), 콘텐츠(4칸), 피드백(1칸)이다. 모두 14칸. 선택과 브랜드 고유는 만들지 않았다.
- 지운 글은 섹션 번호 다섯(`01`~`05`)과 옛 섹션 제목 셋(탐색과 입력, 라이브 카드와 배지, 채팅과 모달)뿐이다.
  옛 제목 "버튼", "화면"은 구역 제목과 글자가 같아 그대로 남는다. `text-inventory.mjs` 로 옮기기 전과 뒤의 글을 다중집합으로 대조했다.

판단이 갈릴 수 있는 곳은 넷이다.

- **맨 위 덩어리를 화면으로 올렸다.** 기준 1절은 히어로에 브랜드 이름, 슬로건, 주요 버튼, 로고만 두게 하고, ADR 0015 는 히어로에만 있던 화면을 옮기라고 한다.
  사이트 머리와 사이드바, 추천 라이브 격자는 홈 화면 한 장이므로 하나의 화면 재현으로 묶었다.
  `<header class="hdr">` 는 `<div>` 로, `<main class="main">` 과 `<section class="sec">` 도 `<div>` 로, `h2.sec-h` 는 `h3` 으로 바꿨다. 문서에 `<main>` 과 `<header>` 가 하나씩이고 `<section>` 과 `<h2>` 는 구역에만 있다.
- **채팅 입력을 브랜드 고유가 아니라 입력에 뒀다.** 쓰임이 "값을 써넣는 칸"이고 md 의 컴포넌트 이름도 `chat-input`(md 325~327)이다.
  칸 안에는 메시지 목록이 든 채팅 패널도 있는데, 칸의 주된 일이 입력창과 그 상태라 칸을 쪼개지 않았다.
- **정렬 메뉴를 입력에 뒀다.** 이름은 메뉴지만 쓰임은 "목록을 열어 값(정렬 기준)을 골라 넣는 칸"이다. 닫힌 모습(인기순 버튼)과 열린 모습(목록)이 한 칸에 나란히 있다.
  ADR 0015 가 쓰임으로 구역을 정하게 했고 기준 1절이 바로 이 경우를 예로 든다. 토스의 MENU 칸도 같은 이유로 입력에 뒀다.
- **채널 머리와 구독 티어 배지를 콘텐츠에 뒀다.** 옛 자리는 화면 섹션이었지만 화면 한 장이 아니라 채널 정보 묶음과 배지 견본이다. 쓰임이 "내용을 담아 보여 주는 것"이다.

## 만들지 않은 구역

- **선택(`selection`)**: md 에 체크박스, 라디오, 스위치, 세그먼트 컴포넌트가 없다. 필터 칩은 모양만 언급된다("알약", md 275, 339). 색, 크기, 선택 상태 값이 없고 옛 프리뷰도 칩을 화면 재현 안에서만 그렸다. 칸을 새로 지어내지 않았다.
- **브랜드 고유(`brand`)**: 채팅 입력이 입력 구역으로 가면서 남는 칸이 없다. 닉네임 색 20종과 역할색은 md 가 토큰으로 옮기지 않았다(md 361).

## 넣은 손끝 반응과 md 근거

| 반응 | 프리뷰 선택자 | md 근거 |
| --- | --- | --- |
| primary, secondary 버튼 hover, 오버레이 5% 를 배경 이미지로 얹음 | `.btn-1:hover`, `.btn-2:hover` | 240(두 갈래 토큰, solid 는 배경 이미지), 307, 337 |
| outlined 버튼 hover, 배경색 자체가 lighten 5% | `.btn-out:hover` | 240 |
| 사이드바 항목 hover, 배경색 흰색 5%(라이트 검정 5%) | `.side-i:hover` | 287, 240 |
| 검색창 초점, 테두리와 캐럿 색 | `.field.fld-live:focus-within`(원래 있었음) | 291 |
| 썸네일 hover, 검정 50% 덧씌움 0.2초 | `.thumb:hover::before`(원래 있었음) | 271, 323 |
| 채팅 입력 초점, 오버레이 | `.chat-live:focus-within`(새 "직접 입력" 줄) | 358 |
| 헤더 전환 `transform .2s ease-in-out` | `.hdr` 의 `transition` | 283 |

- hover 규칙은 `.is-sel` 규칙보다 앞에 뒀다. 나란히 그린 selected 견본은 마우스를 올려도 12% 그대로다(실측).
- **눌림(`:active`)은 하나도 넣지 않았다.** md 는 hover 5% 와 selected 12% 만 규정하고(240, 337) 눌림은 말하지 않는다. selected 를 눌림으로 읽지 않았다.
- tertiary, danger, 아이콘 전용 버튼, 상단 탭, 태그 칩, 팝오버 항목, 모달에는 md 가 정한 반응이 없어 넣지 않았다.
- 채팅 입력의 "활성, 2px 테두리"는 md 가 "활성 클래스가 붙으면"이라고만 적어(358) 어떤 조작으로 켜지는지 알 수 없다. 나란히 그린 견본만 두었다.
- 헤더의 전환은 md 가 값만 적고 무엇이 움직이는지는 적지 않아 선언만 있고 눈에 보이는 변화는 없다.
- 썸네일 덧씌움의 곡선 `cubic-bezier(.65, 0, .35, 1)` 은 옛 프리뷰에 있던 값이다. md 본문은 0.2초만 적는다. 건드리지 않았다.
- 새로 `<button>` 이 된 필터 칩과 탭에는 초점 스타일을 쓰지 않았다. 브라우저 기본 초점 테두리가 보인다.

## 켜고 끄기

| 묶음 | 자리 | 속성 | md 근거 |
| --- | --- | --- | --- |
| 필터 칩 다섯(전체, 게임, 스포츠, 엔터, 기타) | 홈 화면 재현 안 `.tabs` | `data-pv-toggle="aria-pressed"` | 275, 339(필터 칩은 알약). 선택된 칩의 색은 옛 프리뷰 값 그대로다 |
| 상단 탭 넷(게임, e스포츠, 스포츠, 엔터+) | 내비게이션 `top-tabs` 칸의 "직접 선택" 줄 | `data-pv-toggle="aria-selected"`, `role="tablist"` 와 `role="tab"` | 257(상단 탭 링크 17px/21px 800). 현재와 비활성 색은 옛 견본 값 그대로다 |

- 선택지는 진짜 `<button type="button">` 으로 그렸고 스타일은 속성 값(`[aria-pressed="true"]`, `[aria-selected="true"]`)으로 건다. 패널은 없고 숨겨지는 것도 없다.
- 나란히 그린 "현재", "비활성" 견본과 모바일 재현 안의 칩은 그대로 뒀다.
- **홈 화면 재현 안의 필터 칩은 그대로 눌리게 뒀다.** ADR 0015 가 금하는 것은 `role="img"` 화면 안의 실제 컨트롤이다. 홈 화면 재현에는 `role="img"` 를 달지 않았고, 나머지 두 화면(라이브 시청, 모바일 홈)은 `role="img"` 이며 그 안에 누르는 요소가 하나도 없다(`check-base.ts` 가 센다).
  다만 이 칩은 옮기면서 `<span>` 에서 `<button>` 으로 바꾼 것이라 "원래 있던 실제 요소"는 아니다. 구역에 선택 칸이 없는 항목에서 화면 안의 켜고 끄기를 허락할지는 #739 가 정할 일이다.
- 선택된 칩의 글자색은 다크 시트의 델타 규칙이었는데, 속성으로도 걸리도록 토큰(`--chip-on-ink`)으로 바꾸고 델타 규칙을 지웠다. 모바일 재현의 `.m-dark .tab.is-on` 규칙도 같은 토큰 재정의로 바꿨다. 보이는 색은 같다.

## 새로 쓴 글

디자인 설명 문장은 없다. 새로 생긴 글은 다음뿐이다.

- 구역 제목 넷: 입력, 내비게이션, 콘텐츠, 피드백(버튼과 화면은 옛 제목과 같다).
- 칸 이름표 하나: "홈, 데스크톱".
- 상태 이름표 둘: "직접 선택", "직접 입력"(검색 칸에 있던 말을 채팅 칸에도 썼다).
- 조작 안내 둘: "탭을 눌러 보세요", "입력창을 눌러 입력해 보세요".
- 새 시연 안의 글: 탭 넷, "전송", 입력창의 자리 표시 글.
- 합친 더미 데이터 표기 하나. 홈 화면 재현 안에 있던 표기 둘("채널명과 방송 상태는 더미 데이터입니다.", "방송 제목, 채널명, 시청자 수, … 태그는 레이아웃 시연용 더미 데이터입니다.")을 화면 밖 이름표 아래로 빼면서 한 문장으로 합쳤다. 가리키는 낱말은 하나도 빼지 않았다(방송 상태를 목록에 넣었다). 칸의 더미 데이터 표기는 하나라는 약속 때문이다.

## 틀과 기준에 대해 알아낸 것

### 틀이 고쳐져 브랜드 쪽에서 지운 것

첫 틀에는 결함이 넷 있었고 지금 `frame.css` 는 넷을 모두 고쳤다. 그래서 틀을 건드리지 않으려고 브랜드 쪽에 뒀던 우회 규칙을 지웠다.

| 첫 틀의 결함 | 드러난 곳 | 지금의 틀 | 브랜드 쪽에서 지운 것 |
| --- | --- | --- | --- |
| `.pv-stage--stack` 이 `flex-wrap: wrap` 을 물려받음 | 976 폭에서 라이브 시청 화면 칸이 내용 609px 에 상자 523px. 가로 넘침 검사로는 안 잡히는 세로 넘침 | `flex-wrap: nowrap` | 시연 자리 직계 자식 class 열하나의 `width: 100%` |
| `.pv-screen` 에 폭이 없음 | 가로 시연 자리에서 내용 폭으로 쪼그라듦 | `width: 100%` | 화면 재현 틀 둘의 `width: 100vw; max-width: 100%` |
| `.pv-hero` 규칙과 여백 변수가 없음 | 히어로와 구역의 좌우를 맞추려면 틀의 여백 값을 브랜드가 베껴 써야 했음 | 틀이 `--pv-gutter` 를 내줌 | `.hero-wrap` 의 고정 여백. 지금은 `var(--pv-gutter)` 를 읽는다 |
| 칸이 767px 까지 두 열 | 768 폭에서 시연 자리가 약 310px | 899px 이하는 한 열 | (없음) |

휴대폰 틀의 `width: 390px; max-width: 100%` 는 브랜드 화면의 치수라 남겼다.

### 남은 것

1. **자간 변수가 하나다.** `--pv-tracking` 이 구역 제목(22px)과 이름표(12px)에 함께 쓰인다. 치지직은 Pretendard 전 단계가 -0.3px 라 문제가 없지만, 크기 단계마다 자간이 다른 항목(토스)은 한쪽에만 맞는다.
2. **칸의 크기.** 버튼은 변형 다섯을 한 칸에 둔 옛 구성을 그대로 옮겼다. 변형마다 칸을 나누려면 "button, 변형과 상태" 이름표와 변형 공통 스펙 줄의 자리를 새로 정해야 한다. ADR 의 「아직 정하지 않은 것」에 있다.
3. **한 칸이 두 쓰임을 함께 그릴 때.** 채팅 칸(패널과 입력창)과 채널 머리 칸(정보 묶음과 배지)은 쪼개지 않고 주된 쓰임의 구역에 뒀다.
4. **md 가 selected 는 규정하고 눌림은 규정하지 않을 때.** 넣지 않았다. 이런 항목이 더 있을 것이다.
5. **칸이 하나뿐인 구역.** 피드백 구역은 칸 하나가 두 열 중 한 열만 차지해 오른쪽이 빈다.

### 다른 곳에 미치는 것

- **검사기의 전제.** `src/lib/preview-validator.ts` 는 프리뷰에 뿌리 감싸개가 없다고 전제한다(정부 식별 표기 규칙). `main.pv-page` 가 바로 그 감싸개다. 치지직에는 영향이 없지만 KRDS 를 옮길 때 이 규칙이 무뎌진다.
- **대비 총계가 움직인다.** `pnpm audit:contrast:staged` 의 로컬 관측으로 텍스트 요소는 테마마다 300에서 326, 미달 행은 30에서 40 이다(두 테마, 네 폭, 기본과 hover 상태를 합친 수).
  늘어난 미달은 틀의 글이 아니라 브랜드 색이다. md 대로 넣은 hover 가 hover 상태 측정에 새로 잡혔고(초록 면 위 흰 글자는 평소에도 2.7:1 로 미달이다), 새 줄의 "전송"과 비활성 탭이 기존 미달과 같은 색 짝이다.
  본 이행 때는 묶음마다 대비 기준선을 다시 적어야 한다는 뜻이다.
