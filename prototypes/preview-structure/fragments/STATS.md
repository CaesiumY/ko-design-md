## 2. 기존 검사기와 테스트에서 고친 줄, 새로 쓴 검사

- **기존 검증기와 테스트(`src/lib/`, `scripts/`)는 한 줄도 고치지 않았다.** 서빙 파일이 예전과 같은 자리에 같은 꼴로 있으므로 `pnpm validate:previews`, 대비 관측, 면책 띠와 로고 테스트가 그대로 그 파일을 본다. 게이트 목록과 CI 설정도 그대로다.
- 새로 쓴 검사
  - 약속 검사: `contract.ts` 227줄과 `assemble.ts` 의 원본 꼴 검사 부분(약 190줄. 조립에 필요한 읽기와 한 함수에 있다).
  - 어긋남 검사: `repo.ts` 의 `driftOf` 약 25줄.
  - 테스트: `fragments.test.ts` 316줄, 21개. 틀린 구역 순서, 모르는 구역(원본 파일과 서빙 파일 둘 다), 이름표 없는 칸(원본과 서빙 파일 둘 다), 빈 이름표, 겹친 칸 이름, kebab-case 아닌 이름, 모르는 칸 속성, 손으로 쓴 틀 마크업, 빠진 필수 구역, 틀린 구역 제목, 두 항목의 약속과 어긋남, 원본을 고치고 조립하지 않은 상태.

## 3. 온보딩 스테이징 흐름에 더해지는 단계

- 9a 직후에 **조립 단계 하나**: `pnpm previews:check --slug {slug} --src {cache}/preview-src` 와 `pnpm previews:build --slug {slug} --src {cache}/preview-src --out {cache}/preview.html`. 9a2 이후는 조립된 파일을 보므로 그대로다.
- Stage 10 의 복사가 **원본 폴더 복사와 조립**으로 바뀐다. 커밋할 파일이 하나에서 원본 폴더와 서빙 파일로 는다.
- 저자 프롬프트가 HTML 한 장 대신 조각의 문법(README 의 「구역 파일의 칸」)을 알아야 한다. 이 브랜치에서는 프롬프트를 고치지 않았다.
- 자세한 표는 README 의 「온보딩의 임시 폴더 흐름이 바뀌는 곳」이다.

## 4. 새로 생기는 고장 방식

| 고장 | 어떻게 드러나나 |
| --- | --- |
| 원본을 고치고 조립하지 않음, 또는 서빙 파일을 손으로 고침 | `pnpm test` 와 `pnpm previews:check` 가 처음 달라진 줄을 대며 막는다 |
| 검증기, 리뷰어, 대비 게이트가 서빙 파일의 줄 번호로 말함 | 원본의 줄과 번호가 다르다. `pnpm previews:where {slug} <줄>` 로 옮긴다. 서빙 파일이 어긋난 상태에서는 번호가 조립 결과 기준이 된다 |
| 원본 문법 위반(칸 밖의 줄, 두 줄에 걸친 이름표, 닫히지 않은 칸) | 조립이 멈추고 원본 파일과 줄을 댄다. 서빙 파일은 만들어지지 않는다 |
| 조립에 `services/{slug}.md` 가 필요함 | md 가 없거나 `name` 이 없으면 조립이 멈춘다(제목을 거기서 읽는다) |
| 공통 머리로 모든 항목의 `<head>` 가 같아짐 | 치지직에 `<meta name="robots" content="noindex">` 가 더해졌다(바탕 30항목 중 19항목이 이미 갖고 있다). 토스는 `<html …><head>` 와 `</style></head>`, `</body></html>` 이 각각 두 줄로 나뉘고 `defer=""` 가 `defer` 가 됐다. 토스의 `</main>` 앞 빈 줄 하나가 없어졌다. 두 파일에 "조립된 파일이다" 주석 한 줄이 더해졌다. 본문(`<body>` 안)은 그 빈 줄 하나 말고 바탕과 글자까지 같다 |
| 조각 안의 `class="…pv-…"` 를 찾는 검사가 글자로 찾음 | 브랜드 class 이름 가운데 `-pv-` 를 품은 것이 있으면 잘못 막힐 수 있다. 두 항목에는 없다 |

## 5. 고쳐 써야 하는 결정 기록

- **ADR 0002**(한 파일에 두 테마): "검증과 리뷰의 대상은 실제로 서빙되는 문서 한 장"은 그대로 맞다. 다만 사람과 저자가 고치는 것은 그 한 장이 아니라 원본 폴더라는 것, 서빙 파일은 조립 결과라는 것을 더해야 한다.
- **ADR 0006**(저장소 트리가 곧 배포물): 토큰 사이드카처럼 "파생물을 숨기지 않고 커밋하고, 원본과 어긋나면 막는다"에 프리뷰가 두 번째 사례로 들어간다. 원본 폴더 `preview-src/` 도 저장소 트리에 생긴다.
- **ADR 0009**(온보딩 루프가 렌더를 관측): 9a3 이 재는 staged 프리뷰가 조립 결과가 되므로 그 앞에 조립 단계가 끼는 것을 적어야 한다.
- **ADR 0015**(같은 구역을 같은 순서로): 구역의 목록과 순서가 사는 곳(`zones.ts` 한 곳)과, 항목이 순서를 갖지 않는다는 것을 적을 수 있다. 결정 내용은 바뀌지 않는다.

## 6. 토스 변환 스크립트와 손으로 마무리한 곳

- 스크립트: `prototypes/preview-structure/fragments/convert.ts`, 232줄. 공통 바탕의 HTML 한 장을 조각으로 자른다. 조립기의 역이라, 줄 대 줄로 되돌릴 수 없는 줄을 만나면 그 줄을 대고 멈춘다.
- 실행: `pnpm exec tsx prototypes/preview-structure/fragments/convert.ts --slug toss` (출력 폴더 `preview-src/toss/` 가 이미 있으면 덮어쓰지 않고 멈춘다).
- **손으로 마무리한 곳은 없다.** 토스와 치지직 모두 스크립트가 한 번에 멈추지 않고 잘랐고, 조립 결과의 본문은 바탕과 위 4절의 빈 줄 하나 말고 같다. 치지직도 같은 스크립트로 옮겼다(티켓은 토스만 스크립트를 요구한다).
- 확인
  - `dom-diff.ts` 로 바탕 폴더의 파일과 비교: 치지직 `SAME`(16패스, 패스마다 요소 608개), 토스 `SAME`(16패스, 730개).
  - `pnpm validate:previews --slug chzzk`: 막힘 0, 경고 0. `--slug toss`: 막힘 0, 경고 2(바탕과 같은 둘).
  - `pnpm previews:check`: 두 항목 약속 위반 없음, 어긋남 없음.
