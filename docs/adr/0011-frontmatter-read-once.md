# frontmatter 는 한 모듈이 진짜 YAML 로 한 번 읽고, 모든 소비자가 그 결과를 쓴다

항목 DESIGN.md 의 frontmatter 를 저장소 안에서 여섯 곳이 각자 읽어 왔다. 사이트는 손으로 짠 파서(`buildDoc`)로 읽었는데, gray-matter 가 브라우저 번들에 Node 의 `Buffer` 를 끌어와 hydration 을 깨뜨렸기 때문이다. 검증기는 `yaml` 로, 토큰 추출기는 줄 단위 정규식(`mapRows`)으로 읽었다. 색 어긋남 검사·`audit:oklch`·날짜 검사는 각자의 정규식으로 읽었다. 공식 린터는 따로 `yaml` 로 읽는다.

독자가 여럿이니 같은 줄을 서로 다르게 읽는 모양이 계속 나왔다. 검증기는 그 모양을 하나씩 찾아 막는 규칙으로 대응했다. `misread-frontmatter-value`·`nonbare-frontmatter-key`·`list-frontmatter-value`·`quoted-token-value`·`unreadable-token-map`·`block-scalar-token-value`·`noncanonical-token-indent` 와, 원인 하나에 메시지 하나만 내도록 이들을 서로 억제하는 장치다. 2026-10-19 기준으로 이 부분이 `draft-validator.ts` 의 약 4분의 1, 그 테스트의 약 30% 를 차지했다. 같은 시기 검증기 커밋 일곱 개(#447·#449·#453·#454·#488·#492·#494)가 전부 이 화해 작업이었고, #454 는 리뷰 다섯 라운드 동안 매번 새 모양을 찾아냈다.

그래서 독자를 하나로 모은다. `src/lib/frontmatter.ts` 의 `readFrontmatter` 가 `yaml`(공식 린터와 같은 라이브러리) 로 한 번 읽는다. 키마다 값, 줄 위치, 줄 끝 주석, 그리고 "비어 있음" 표시를 돌려준다. 사이트는 빌드할 때 Vite 가상 모듈로 그 결과를 JSON 으로 받는다(`virtual:preview-slugs` 와 같은 방식). 그러면 브라우저 번들에 파서가 들어가지 않으므로 손 파서를 둔 이유가 사라진다. 토큰 추출기·색 어긋남 검사·`audit:oklch`·날짜 검사·검증기도 이 모듈만 쓴다. 다르게 읽힐 자리가 없어지므로 위의 화해 규칙들은 지운다.

## Considered Options

- **화해 규칙을 계속 늘린다.** 지금까지의 방식이다. 새 모양이 나올 때마다 규칙과 억제 장치가 함께 늘고, 그 사이 사이트가 값을 조용히 다르게 읽은 채 배포될 수 있다. 막는 쪽이 늘 한 발 늦다.
- **사이트가 브라우저에서 `yaml` 로 읽는다.** 2026-10-03 평가에서 카탈로그 출력은 바이트 단위로 같았다. 그러나 클라이언트 JS 가 gzip 기준 29KB 늘고, 첫 읽기가 77~111ms 걸렸다(손 파서는 1ms).
- **읽은 결과를 JSON 파일로 커밋한다.** 토큰 사이드카와 같은 방식이다. 커밋할 파생물과 그것을 지키는 어긋남 검사가 하나씩 더 생긴다. 사이트만 쓰는 값이라 저장소 트리로 배포할 이유도 없다(ADR 0006 이 다루는 것은 소비자가 가져가는 파일이다).
- **사이트·검증기·추출기만 옮긴다.** 남은 정규식 독자와 새 모듈 사이에 새로운 "다르게 읽기"가 생긴다.

## Consequences

- **빈 값은 사이트 빌드를 실패시킨다.** 2026-10-03 평가에서 유일하게 진짜 후퇴였던 경우를 막기 위해서다. YAML 은 맨 `name:` 을 `null` 로 읽는데, 이것이 기본값으로 떨어지면 이름이 슬러그로 조용히 바뀐다. 검증기는 지금처럼 필드 규칙(`bad-name` 등)으로 막는다.
- **토큰 값에 따옴표를 써도 된다.** 모두가 같은 값을 읽기 때문이다. 따옴표 친 hex 는 여전히 `non-oklch-token-value` 가 막는다.
- **들여쓰기 칸 수는 상관없다.** 다만 토큰 맵 아래에 또 맵이 오면 막는다. 중첩하면 참조 이름이 `{colors.blue.500}` 로 바뀌어 사이드카·린터가 기대하는 모양과 달라지기 때문이다(원래 한 단계 중첩하는 typography 는 제외).
- **frontmatter 가 YAML 로 읽히지 않으면 날짜 검사도 판정하지 못했다고 막는다.** 건너뛰면 검사하지 않은 것이 통과로 보인다.
- **토큰 사이드카는 지금처럼 커밋하고 `tokens:check` 로 지킨다.** 만드는 쪽만 이 모듈로 바뀐다.
- **화해 규칙을 지울 때는 규칙마다 "잡던 입력이 이제 어디로 가는가"를 적고, 그 입력을 테스트 픽스처로 남긴다.**
- **사이트와 YAML 이 다르게 읽는 경우를 막는 규칙은 다시 만들지 않는다.** 그런 경우가 보이면 그것은 이 모듈을 거치지 않는 독자가 생겼다는 신호이고, 고칠 곳은 그 독자다.
- 구현은 세 번에 나눠 넣는다. ① 모듈과 사이트 → ② 추출기·색 어긋남 검사·`audit:oklch`·날짜 검사 → ③ 검증기 전환과 화해 규칙 삭제, `CLAUDE.md` 의 해당 단락 정리 순서다. 규칙은 모든 독자가 옮겨진 뒤에만 지울 수 있다.
