# 대비 잡은 얇은 프리뷰도 막는다

PR 614 의 외부 기여 항목 둘(치지직, 라프텔)은 테마마다 텍스트 요소가 79개, 51개인 프리뷰로 들어왔다. 카탈로그에서 가장 얇았지만 그 수로 판정하는 검사가 없어 모든 게이트를 통과했고, 사람이 눈으로 보고서야 보강했다. 그래서 CI 의 `contrast` 잡이 **측정한** 텍스트 행의 요소 수가 하한 `MIN_TEXT_ELEMENTS` 아래면 막는다. 이것은 ADR 0007 이 정한 "기준선 어긋남만 막는다"와 다른 축이다. 대비 수치가 표에서 움직였는지가 아니라 프리뷰가 보여 주는 분량을 보므로, 기록값과 측정값이 같아도 막힌다.

하한은 고정값 80이다. 보강 전 치지직(79)과 라프텔(51)은 막고, 따로 보강 없이 남아 있는 가장 얇은 항목(2026-11-09 기준 여기어때 94)은 통과시키는 자리다. 결정은 2026-11-09 PR 614 회고에서 했고, PR 676 이 싣는다.

## Considered Options

- **경고로만 둔다**(회고의 첫 제안). vitest 에는 경고 상태가 없고, 콘솔 경고와 게이트의 warn 줄은 PR 614 때처럼 아무도 읽지 않으면 그대로 들어온다. ADR 0007 이 "전부 warn" 을 버린 이유와 같다.
- **카탈로그 중앙값의 비율로 둔다**(회고의 첫 제안, 중앙값의 40%). 당시 중앙값(약 246)의 40%는 약 98이라 여기어때가 그날 바로 실패한다. 두꺼운 항목이 늘수록 하한이 올라가, 아무도 손대지 않은 항목이 다른 PR 에서 실패한다.
- **기준표의 숫자만 검사한다**(PR 676 의 첫 커밋). 기준표의 수는 사람이 붙여 넣고, `elements` 는 정확 비교에서 빠진 수라 손으로 올려 적으면 통과한다(claude-review 의 지적). 그래서 측정값에 걸고, 기준표 검사는 붙여 넣는 순간 먼저 걸리도록 같은 상수로 남긴다.
- **서로 다른 행 수(`measured`)로 잰다.** 카드 사본을 접어 세므로 더 정직해 보이지만, 삼성(52)과 보강 전 치지직(48)이 붙어 있어 둘을 가르지 못한다.
- **대비 잡 밖의 별도 검사나 다른 종료 코드로 뗀다.** 요소 수는 대비 수집기가 재는 값이라 따로 재려면 같은 렌더를 한 번 더 돌려야 한다. 종료 코드는 CI 가 0 이 아니면 모두 실패로 읽으므로 새 코드를 읽을 곳이 없고, 원인은 실패 출력의 별도 절이 이름으로 말한다.

## Consequences

- 종료 코드 3 은 이제 기준선 어긋남과 얇은 프리뷰를 함께 뜻한다. 실패 출력은 둘을 다른 절로 찍고, 얇은 프리뷰 절은 고치는 법(md 가 말하는 상태와 화면 목업을 더한다, 카드 복사는 답이 아니다)을 말한다.
- `elements` 는 카드를 반복해도 오르는 거친 수라, 적게 보여 주는 프리뷰는 잡지만 반복으로 부풀린 프리뷰는 못 잡는다. 후자는 여전히 리뷰의 몫이다.
- `elements` 는 화면의 모든 글자가 아니라 대비 수집기가 읽는 글자다. 비활성(`:disabled`, `aria-disabled="true"`), 숨김, 투명, 잘림, 가려진 글자는 세지 않는다. 그래서 ADR 0007 이 클래스로만 그린 비활성 시연에 권하는 선언은 이 수를 줄이고, 비활성 상태를 더해도 수는 오르지 않는다. 그 선언으로 하한 아래로 내려간 프리뷰도 답은 같다. 읽히는 상태와 화면 목업을 더 보여 준다. 실패 안내도 "비활성이 아닌 상태"를 더하라고 말한다.
- 기준표에 줄이 없는 새 슬러그도 하한을 받는다. 하한이 겨냥하는 경우가 바로 새 항목이기 때문이다.
- 온보딩 스킬 루프(Stage 9a3 의 로컬 대비 관찰, ADR 0009)는 아직 이 하한을 모른다. 그래서 스킬로 만든 얇은 프리뷰는 CI 에서 처음 막힌다. 스킬 배선은 이슈에서 합의한 뒤 바꾼다.
- 규칙 문서와 안내 문서는 하한의 수를 옮겨 적지 않고 상수 이름만 가리킨다(이 ADR 의 수는 결정한 날의 기록이다). 수와 그 근거는 `src/lib/contrast-baseline.ts` 의 상수 주석 한 곳에 있다.
