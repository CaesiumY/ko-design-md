# 항목의 DESIGN.md 는 그 자체로 DESIGN.md 명세 문서다

Google Labs 가 DESIGN.md 명세와 공식 린터를 공개했을 때, 처음에는 항목 파일을 그대로 두고 어댑터가 명세 모양의 뷰만 만들었다. 그러나 토큰을 본문 코드 블록에 둔 항목 파일을 공식 린터는 토큰으로 읽지 못했으므로, 토큰을 frontmatter 로 옮겨 항목의 DESIGN.md 자체를 명세 문서로 만들었다 — 사이트를 거치지 않고 파일을 가져간 소비자도 공식 도구가 해석하는 문서를 받게 하려는 것이다. 명세를 따르려면 브랜드 발행값을 버려야 하는 자리는 고치지 않고 기록하며, 명세에 자리가 없는 인용과 프로비넌스를 지키기 위해 항목의 DESIGN.md 는 그대로 두고 표준 도구용 DESIGN.md 는 요청할 때마다 계산해 내는 두 번째 표현으로만 둔다.

## Considered Options

- 어댑터 뷰만 두고 항목 파일은 그대로 — 파일을 직접 가져간 소비자에게는 명세가 해석하지 못하는 문서가 간다.
- 명세 형식으로 완전 전환 — 인용과 프로비넌스를 담을 자리가 없다.
- 명세 규칙을 저장소 안에 다시 적은 자체 검증기 — 섹션 목록 하나를 이미 네 곳에 복제해 손으로 맞추고 있었다.
