# 사이트는 항목을 주소로 넘기는 붙여넣기 프롬프트를 내놓지 않는다

#530(2026-10-12)은 상세 페이지 사이드바에 핸드오프 프롬프트를 두었다. 항목 DESIGN.md 의 주소 한 줄과, 그 디자인으로 지금 프로젝트 UI 를 구현하라는 지시 한 줄이다. 이 두 줄은 붙여 넣은 쪽이 그 주소를 직접 열 수 있을 때만 동작한다. 2026-10-19 에 그렇지 않은 환경 두 곳이 보고됐다.

첫째는 제미나이 웹이다. 브라우징 도구가 HTML 이 아닌 응답이면 호스트·크기와 상관없이 `URL_FETCH_STATUS_MISC_ERROR` 를 냈다. 비교용 주소 7개(도메인 4곳)로 확인했는데, 113바이트 `robots.txt`, `llms.txt`, GitHub raw, 다른 사이트의 `text/markdown` 문서가 모두 실패했다. HTML 만 열렸고, 상세 페이지는 frontmatter 근처에서 잘려 `## Known Gaps` 까지 닿지 못했다. 그런데 핸드오프 프롬프트를 그대로 넣었을 때 제미나이는 이 오류를 먼저 알리지 않았다. 오히려 문서를 다 못 읽어도 오류 없이 짐작한 "토스 느낌" 값으로 코드를 고친다고 스스로 설명했다. 둘째는 Claude Code 클라우드 환경이다. 네트워크 허용 목록이 이 호스트를 막아 curl 은 프록시 403 을, WebFetch 는 `ENOTFOUND` 를 받았다. 공개 DNS 는 정상으로 해석한다.

사이트는 프롬프트를 붙여 넣는 사람의 환경을 알 수 없고, 실패가 조용할 수 있다. 정확한 발행값이 이 카탈로그의 가치인데, 조용한 실패는 그럴듯한 가짜 값을 그 자리에 놓는다. 그래서 상자를 걷어 낸다. 같은 일은 이미 두 길이 한다. 사이드바의 전체 복사·다운로드는 본문 자체를 넘기므로 네트워크가 필요 없다. 코딩 에이전트에는 `use-design-md` 스킬이 있다.

이 결정의 범위는 **사이트가 사람에게 내미는 붙여넣기용 프롬프트**뿐이다. `use-design-md` 스킬과 `/services/{slug}/DESIGN.md` 주소는 범위 밖이다. 그 주소는 표준 도구와 스킬이 쓰므로 그대로 둔다.

## Considered Options

- **상자에 "코딩 에이전트용" 표시와 웹 채팅 안내를 단다.** 이 상자는 읽지 않고 바로 붙여 넣는 짧음이 정체성이었다. 그래서 안내를 지나치는 바로 그 사용자에게서 조용한 실패가 난다.
- **원문 주소의 Content-Type 을 `text/markdown` 으로 바꾼다.** 효과가 없다. 제미나이는 다른 사이트가 `text/markdown` 으로 내는 문서도 같은 오류로 열지 못했다. 바꾸면 브라우저가 원문을 화면에 바로 보여 주던 것만 잃는다(라우트 주석이 `text/plain` 을 고른 이유).
- **프롬프트가 HTML 상세 페이지 주소를 가리키게 한다.** 제미나이는 열지만 앞부분에서 잘린다. 코딩 에이전트는 원문 대신 무거운 HTML 을 받는다.

## Consequences

- `design_md_copy` 는 다시 전체 복사 두 표면(`design-md-hero`·`design-md-tab`)만 센다. 2026-10-12~19 사이의 이벤트에는 surface `handoff-prompt` 가 섞여 있을 수 있다.
- 용어집에서 "핸드오프 프롬프트"를 뺐다. 이름이 비슷한 번들(handoff bundle)은 그대로다.
