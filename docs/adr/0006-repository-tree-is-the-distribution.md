# 저장소 트리가 곧 배포물이다

카탈로그의 산출물은 사이트 빌드를 거치지 않고도 소비된다 — DESIGN.md 는 LLM 컨텍스트와 다른 저장소로 복사되고, 토큰 사이드카는 소비자 스킬이 GitHub raw 에서 직접 받아 가며, 소비자 스킬 자체는 skills.sh·플러그인 마켓플레이스·사이트의 well-known 경로가 같은 파일을 가져간다. 그래서 파일은 저장소에 놓인 모양 그대로 밖에서도 온전해야 하고, 같은 내용이 채널마다 다른 사본으로 갈라질 여지를 두지 않는다.

## Consequences

- DESIGN.md 의 로고는 사이트 밖에서도 풀리는 절대 주소로 적는다. 사이트 안에서만 쓰는 프리뷰는 상대 경로를 쓴다 — 상대 경로는 복사된 파일에서 죽은 참조가 됐다.
- 토큰 사이드카는 빌드 산출물로 숨기지 않고 커밋하며, 파생물이므로 DESIGN.md 와 어긋나면 막는다. 사이트 런타임도 이 파일만 읽는다.
- 사이트가 발행하는 소비자 스킬은 사본이 아니라 배포되는 그 파일의 바이트이고, 요약값도 서빙하는 바이트로 계산한다.
- 공개 스킬과 내부 스킬의 경계는 디렉터리를 옮기지 않고 선언과 테스트로 긋는다. 스킬 스캐너는 어느 쪽이든 같은 디렉터리를 보므로, 옮겨도 발견 방식은 그대로이고 저장소 안 사용성과 외부 링크만 잃는다.
