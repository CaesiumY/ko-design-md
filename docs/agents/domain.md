# 도메인 문서

엔지니어링 스킬이 코드베이스를 탐색할 때 이 저장소의 도메인 문서를 어떻게 소비하는지.

## 탐색 전에 읽을 것

- 저장소 루트의 **`CONTEXT.md`**, 또는
- 루트에 **`CONTEXT-MAP.md`** 가 있으면 그것 — 컨텍스트마다 `CONTEXT.md` 하나를 가리킨다. 주제에 해당하는 것을 각각 읽는다.
- **`docs/adr/`** — 지금 작업할 영역에 닿는 ADR 을 읽는다.

이 파일들이 없으면 **조용히 넘어간다.** 없다고 알리지 말고, 미리 만들라고 제안하지도 말 것. `/domain-modeling` 스킬(`/grill-with-docs`·`/improve-codebase-architecture` 를 거쳐 도달한다)이 용어나 결정이 실제로 확정될 때 필요한 만큼 만든다.

## 이 저장소의 레이아웃 — single-context

모노레포 신호(`pnpm-workspace.yaml` · `package.json` 의 `workspaces` · `packages/*`)가 없으므로 루트 `CONTEXT.md` 하나와 `docs/adr/` 를 쓴다. **둘 다 아직 없고, 그게 정상이다.**

```
/
├── CONTEXT.md
├── docs/adr/
│   └── 0001-<결정>.md
└── src/
```

**카탈로그 정책과 검증 규칙의 정본은 `CLAUDE.md` 다.** `CONTEXT.md` 는 용어집, `docs/adr/` 는 결정 기록이다 — `CLAUDE.md` 의 규칙을 그리로 복제하지 말 것. 이 저장소는 같은 규칙이 두 곳에 적혀 서로 어긋나는 일을 여러 번 겪었다.

## 용어집의 어휘를 쓴다

출력이 도메인 개념에 이름을 붙일 때(이슈 제목, 리팩터 제안, 가설, 테스트 이름) `CONTEXT.md` 에 정의된 용어를 쓴다. 용어집이 명시적으로 피하는 동의어로 흘러가지 말 것.

필요한 개념이 아직 용어집에 없으면 그것이 신호다 — 프로젝트가 쓰지 않는 말을 지어내는 중이거나(재고할 것), 진짜 공백이다(`/domain-modeling` 에 적어 둘 것).

## ADR 충돌을 드러낸다

출력이 기존 ADR 과 어긋나면 조용히 덮어쓰지 말고 명시한다.

> _ADR-0007 과 모순된다 — 하지만 다시 열 가치가 있다, 왜냐하면…_
