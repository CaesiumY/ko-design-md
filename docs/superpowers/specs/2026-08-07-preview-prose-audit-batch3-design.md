## 실명 자연인에 발명값이 붙어 있었다

vapor-ui 05 Data 섹션의 멤버 표는 `최준영`(Squad Lead) · `이태성`(CDO)을 행으로 렌더하며
`활성` 계정 상태와 `컨테이너 12 / 8`을 붙인다. **이 두 사람은 실존 인물이다** — md:27 과
md:655 가 goorm 공식 블로그[src:2]를 근거로 Vapor Squad 신설(2025-04)과 두 직함을 싣는다.
나머지 두 행(`김지원` Frontend · `박서연` Design)은 md 0 건, 즉 존재하지 않는 사람이다.

`design-md-preview-disclaimer.test.ts` 의 `FABRICATED_DATA_SITES` 는 그 주석이 밝히듯
**"실명 제3자(기업)에 붙는 발명값"** 을 상정하고 쓰였다. 여기는 **실명 자연인**이라
기준보다 약한 자리가 아니라 **더 강한** 자리다. 상단 배너가 열거하는
"상품·가격·평점·거래·채용"도 계정 상태·자원 사용량·가상 인물을 덮지 못한다.

캡션은 yeogi 가 만든 분리를 그대로 따른다 — **근거 있는 쪽과 발명된 쪽을 한 문장에서
가른다**(yeogi: 티어 이름은 md 근거, 혜택 설명은 더미).

같은 파일 07 섹션은 실재 호스트명(`console.goorm.io`) 위에 컨테이너 목록을 그리면서
`총 사용량 12.4GB / 50GB` 와 컨테이너 4행(이름·상태·메모리)을 발명한다. 위 논증이
그대로 적용되는 자리인데 05 만 라벨하고 07 을 비워 두면 같은 파일 안에서 기준이 갈린다.
**두 곳 다 붙였다.**

vapor-ui 에는 `.screen` / `.screen-mock` 래퍼가 없어 목업 내부 배치 금지 규칙이 걸리지
않는다. `.container` 는 블록 부모이므로 #254 의 컬럼-flex 팽창 위험도 없다.

## 가드가 분리를 지키지 못했다 — 리뷰가 변조로 실증했다

초판 가드는 `["실제 직함", "계정 상태", "컨테이너 수", "가상의 인물"]` 이었다.
서브에이전트가 캡션을 두 가지로 변조해 돌려 보니 **둘 다 초록으로 통과했다**:

- **분리 역전** — 실존 인물을 "가상의 인물" 이라 부르고 발명값을 "실제 직함" 이라 부름
- **평탄화** — 고유명사를 전부 지우고 네 어구를 한 줄에 나열

원인은 가드가 캡션 전체를 이어붙인 문자열의 **부분일치** 검사이기 때문이다
(`design-md-preview-disclaimer.test.ts`). **추상 어구만으로는 어떤 부분문자열 집합도
분리를 인코딩할 수 없다.** 그래서 초판의 "`컨테이너 수` 를 지우면 실패한다" 확인은
*각 리터럴이 필수*임만 증명했지 *분리가 보호된다*는 것은 증명하지 못했다.

**vapor-ui 는 고유명사를 하나도 박지 않은 유일한 항목이었다** — yeogi `ElitePlus` ·
teamsparta `'국비지원'` · baemin `이마트슈퍼무배` · kyobobook `'베스트'` ·
gmarket `'공식' 배지` 는 전부 박는다. 근거 축에 `Squad Lead`, 발명 축에 `김지원` 을
박자 **위 두 변조가 모두 실패한다**(역전 변조로 재확인했다).

## md 자신의 예시를 고쳐 실은 자리가 두 슬러그 모두에 있었다

이번 배치에서 새로 드러난 결함 유형이다. **md 가 tsx 예시로 실은 문자열을 프리뷰가
변형해 렌더한다** — 값이 md 에 있으므로 grep 은 통과하고, 변형분만 근거가 없다.

| 슬러그 | md | 프리뷰(정정 전) |
| --- | --- | --- |
| gmarket | md:528 `무료 배송 쿠폰` | `무료 배송 쿠폰 무제한` |
| gmarket | md:529 `적립 2배` | `스마일캐시 적립 2배` |
| gmarket | md:551 `지금 가입하고 혜택 받기` | `지금 가입하고 무료배송 받기` |
| vapor-ui | md:580 `삭제하면 복구할 수 없습니다` | `삭제하면 복구할 수 없다` |

gmarket 세 건은 **실재하는 유료 멤버십(스마일클럽)의 혜택 주장을 강화하는 방향**이라
특히 나쁘다. 넷 다 md 문자열로 되돌렸다.

## 나머지 정정

- **`AVATAR · … 32px (lg 40px)`** — md:547 은 아바타를 `32×32(기본)` 로만 싣고 `lg` 를
  명명하지 않는다. `size-component-lg: 40px`(md:316)은 컴포넌트 공통 사다리지 아바타
  변형이 아니다. baemin `pill 48px` 선례대로 `lg 40px는 이 프리뷰의 재현` 으로 바꿨다.
- **`table th 12px`**(라이트 07 캡션) — md:551 은 th 를 **600 / 13px** 로 싣는다. 이 프리뷰는
  th 를 두 값으로 렌더한다 — `.vp-table th` 13px(md 준수)와 `.mock-table th` 12px. 캡션이
  md 가 반증하는 값을 양옆의 md 근거값(본문 14px = md:284, 헤어라인 1px gray-200 = md:324)과
  **같은 레지스터로, 아무 표시 없이** 실었다. `목업 표 th 12px는 이 프리뷰의 재현` 으로 분리.
- **다크 `focus 상태 — blue-400 ring 25%`** — 아래 항 참조.
- **`품절 상품의 CTA가 대표 사례입니다`** — md:336 은 disabled 를 opacity 40% 로 싣고
  md:339 tsx 가 `<Button type="cta" disabled>품절</Button>` 이므로 **예시라는 사실은 맞다.**
  없는 것은 **대표성**이다. CLAUDE.md 의 "상대평가를 쓰지 말 것" 과도 부딪힌다 —
  `그 예입니다` 로 낮췄다.

## 내가 성과라고 적었던 것이 결함이었다

초판 스펙은 vapor-ui 의 테마 분기를 **잘 된 사례**로 적었다 — 라이트
`focus 상태 — blue-500 ring 18%`, 다크 `blue-400 ring 25%`, 각 파일 CSS 도 그 값이므로
toss(#236)의 `white selected segment` 와 반대라고 썼다.

**절반만 맞았다.** md:233 의 alias 표가 받쳐 주는 것은 **색상** swap(`blue-500 → blue-400`)
뿐이다. md:483 은 포커스 링을 **한 번만**, 테마 조건 없이 `blue-500 ring(투명도 18%)` 으로
싣고 **md 전문에 25% 는 없다.** 다크 파일의 `--vp-ring-primary: … / .25` 와 산문이 맞는 것은
**파일 자기 일관성이지 md 근거가 아니다.**

내 검증이 프리뷰를 **md 가 아니라 자기 자신과** 대조하고 통과 판정을 냈다. 이 계열이
반복해 배운 것의 변주다 — 대조 대상을 잘못 잡으면 일치는 아무것도 보증하지 않는다.
`불투명도 25%는 이 프리뷰의 재현` 으로 분리했다(색상은 md:233 근거가 있으므로 남긴다).

## grep 이 다섯 번째로 오도했다 — 이번엔 접두사 생략

`sm 28` · `md 32` · `lg 40` · `xl 48` 이 리터럴 0 건이었으나 md:314-317 에
`size-component-sm: 28px` … `-xl: 48px` 로 실재한다. 프리뷰가 **토큰 접두사를 떼고**
압축 표기했을 뿐이다.

이 계열의 거짓 음성이 매번 다른 방식이었다:

| 방식 | 사례 |
| --- | --- |
| 어순 반전 | `sticker-shadow` → `shadow-sticker` |
| 한↔영 | `엘리트 플러스` → `ElitePlus` |
| 범주↔실물 | 캡션 `평점` → 렌더 `★ 4.9 (2,184)`, `사은품` → `+미니어처 2종` |
| 접두사 생략 | `sm 28` → `size-component-sm: 28px` |

## gmarket 캡션 3개는 카드 커버리지로는 정확했다

두 개가 같은 문구지만 **서로 다른 카드**에 붙어 있다 —
`아이템 카드 — Gallery / Price 상태`(light:1304)와 `아이템 카드 — List variant`(light:1374).
각 카드가 자기 상품 데이터를 렌더하므로 둘 다 필요하다. 세 번째(light:1405)는
주문·배송 목업을 덮는다.

계획 단계에서 **캡션이 `평점` 을 열거하는데 렌더에 별점이 안 보인다**는 의문을 남겼는데,
`★ 4.9 (2,184)` 로 실재했다. 앞선 grep 이 `평점` 이라는 **단어**만 찾아 캡션 자신의 문구
두 건만 잡았던 것이다. **캡션이 렌더를 덮는지 볼 때는 범주로 읽어야 한다.**

**그러나 커버리지 질문을 카드 단위로만 물은 것이 실수였다.** 세 캡션은 아이템 카드와
주문 목업에만 붙어 있고 **01 컴포넌트 그리드에는 하나도 없다.** 거기서 실재 멤버십·
실명 배송 서비스에 대해 발명 주장을 한다 — 팝오버 `스마일클럽 혜택`, 배너
`스마일클럽 7일 무료`, 아코디언 `오늘(수) 도착` · `스마일배송 · 오후 6시 이전 도착 예정`,
`재고가 3개 남았습니다`, 다이얼로그의 취소 정책 서술. 배너 열거에 멤버십 혜택·배송 SLA·
재고·취소 정책은 없다. 섹션 헤드에 캡션 하나를 붙였다.

## 다음 패스로 넘기는 관찰 — 목업 카피 어조 (권장: 고칠 것)

md:31 은 Vapor 의 product surface 카피를 **존댓말(~니다/~습니다)** 로, 버튼은 **짧은
명령형 동사**로 못박고[src:5] md:597 이 Do 로 굳힌다. 같은 줄에서 **두 레지스터를 명시적으로
분리**한다 — 카탈로그 메타 서술은 `~다` 평서체, Vapor 제품 카피는 존댓말.

프리뷰는 버튼(`저장` · `삭제` · `시작하기`)은 맞게 썼고 `row-label` · `caption` 등
카탈로그 주석이 평서체인 것도 옳다. **그런데 목업 UI 안의 카피가 전부 평서체다** —
툴팁 1 건을 이번에 고쳤고 **파일당 약 16 곳이 남는다**:

| 표면 | 예 |
| --- | --- |
| Callout 8 | `배포가 완료되었다.` · `다른 페이지로 이동하기 전에 저장한다.` |
| rc-desc 4 | `브라우저에서 바로 컨테이너를 띄워 개발한다.` |
| Toast 2 | `컨테이너가 시작되었다.` · `빌드에 실패했다. 로그를 확인한다.` |
| helper · placeholder · checkbox 3 | `로그인 ID로 사용된다.` · `리전을 선택한다` · `동의한다` |

**이번 배치에 넣지 않았다** — 32 줄 레지스터 재작성은 diff 자체가 리뷰 대상이라 부록으로
끼울 성질이 아니다. 툴팁만 넣은 이유는 **그것이 레지스터 문제가 아니라 md 예시 변형**
이어서, 위 gmarket 세 건과 같은 결함 클래스이기 때문이다.

**초판이 유예 근거를 잘못 댔다.** "앞선 라운드가 목업 카피를 라벨만 붙이고 고쳐 쓰지
않았다"(baemin `마법주문어` · gmarket 상품명)고 적었는데, 그 선례들은 *실명 브랜드에 붙은
발명 데이터*라 라벨이 해법인 경우다. 여기는 *레지스터*이고 md 가 출처와 함께 싣는
**시스템 속성**이라 라벨로 처리할 수 없다. **유예 결론은 범위 근거로는 옳지만 선례
근거로는 틀렸다.** 고치는 쪽을 권한다.

### 계수 단위를 한 번 헷갈렸다

전수 회귀가 캡션 **48** 개로 나와 2 차의 "23 곳" 과 어긋나 보였다. 실제로는 단위가 달랐다 —
