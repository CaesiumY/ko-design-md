## 배경

## H-2 시작 지점 — "172문장" 은 양방향으로 틀렸다

H-1 스펙의 계수 술어는 `light.html` 의 **텍스트 노드** 중 한글을 포함하고 18자 이상이며
`(다|음|임|니다|습니다|한다|된다)` 로 끝나는 것을 셌다. 이 술어가 네 가지를 잘못 처리한다.

**과다 계상 세 가지**

1. **감사 장치를 감사 대상으로 셌다.** D-1·E 가 넣은 고지 스트립과 `.catalog-dummy`
   캡션이 그대로 포함됐다 — krds 29 중 **9개**가 이것이다.
2. **목업 화면 안 카피를 셌다.** `본인 인증 시 등록된 이름이 자동 입력됩니다` ·
   `소득세·부가세 등 국세를 한 곳에서 납부합니다` 같은 문장은 표시 데이터이지 카탈로그가
   디자인 시스템에 대해 하는 서술이 아니다 — krds 29 중 **16개**. 표시 데이터는 더미
   라벨링으로 처리한다는 D-1 결정의 소관이다.
3. **인라인 태그에서 잘린 조각을 문장으로 셌다.** socar 의 `이며 옵션으로 1px 흰 보더를
둔다` · `으로 강등한다` 는 `<code>` 태그 때문에 갈라진 한 문장의 파편이다.

**과소 계상 한 가지 — 이쪽이 더 중요하다**

4. **명사구 부제를 통째로 놓쳤다.** krds 의 `caption` 9개는
   `48px 필드 · 6px radius · 2px primary-50 포커스` 처럼 종결어미가 없다. 종결형을
   요구한 술어가 이것들을 0으로 셌다. **krds 는 "4건" 이 아니라 13건이었다.**

즉 172 는 큰 쪽으로도 작은 쪽으로도 틀린 수치이며, **"문장" 이라는 단위 자체가 잘못됐다.**

## H-2a. socar — 14개 노트 중 13개는 md 가 지지한다

**손대지 않은 것이 결과의 대부분이다.** `p.panel-note` 14개, 패널 제목 18개,
히어로 리드를 `services/socar.md`(646줄)와 주장 단위로 대조했고 대부분 정확했다 —
예: Input 노트의 `세 variant 모두 focus 시 보더가 blue-200` 은 md:425·433·441 이 각각
filled·outlined·underline 에 대해 적고 있어 **셋 다 확인된다**. Tips(md:526·536),
DatePicker/TimePicker(md:477), Checkbox(md:361·365), Carousel(md:518),
Skeleton(md:408), SegmentedControl(md:502), 히어로 리드(md:61·90·156·246·568·604)도
모두 지지된다.

정정은 3건이다.

| 위치                                | 결함                                                         | md 근거                                                                                                                                                    |
| ----------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Chip 노트 + `.sf-chip.selected` CSS | 선택 배경을 `information-weak` 로 적고 CSS 도 그 토큰을 썼다 | md:353 은 Chip 선택 배경을 **`blue-50`** 으로 적는다                                                                                                       |
| SelectionBox 노트                   | `blue-50 배경에 1px inset 링을 입힌다` 고 **단정**           | md:390 은 선택색을 `primary-regular` 계열로만 적고 **"부분 스펙 컴포넌트라 정확한 선택 보더 토큰은 doc 페이지·스크린샷과 함께 확인해야 한다"** 고 유보한다 |
| Accordion 노트                      | `셰브론은 펼침 시 180° 회전한다`                             | md:332 는 `질문 + 셰브론의 trigger 행` 까지만 적는다                                                                                                       |

### `blue-50` 이 컴포넌트 둘 사이에서 뒤바뀌어 있었다

**md 가 그 값을 부여한 컴포넌트(Chip)에서는 빠지고, md 가 유보한 컴포넌트(SelectionBox)에
붙어 있었다.** 노트를 하나씩 읽으면 둘 다 그럴듯하다 — Chip 의 `information-weak` 도
값이 맞고(md:85·125 가 `blue-50` 과 같은 `oklch(0.966 0.017 248)` 임을 보인다),
SelectionBox 의 `blue-50` 도 프리뷰 CSS 와 일치한다. **주장 단위 표를 만들어 같은 값이
어디에 붙어 있는지 가로로 봐야** 드러난다.

`information-weak` 를 고치는 이유는 값이 틀려서가 아니라 **의미가 틀려서**다 — 발행명이
`status-information-weak` 인 status 계열 시맨틱 토큰을(md:71) 선택 상태에 쓰면, 카탈로그를
보고 구현하는 쪽이 그 의미를 그대로 복제한다. 값이 같아 **렌더는 픽셀 단위로 불변**이다
(측정: `.sf-chip.selected` 배경 `oklch(0.966 0.017 248)` 전후 동일).

### 삭제가 아니라 재현 표기

SelectionBox 와 Accordion 은 렌더를 그대로 두고 산문만 고쳤다. 프리뷰 CSS 는 실제로
`rotate(180deg)` 와 inset 링을 구현하므로 **시연을 지우면 보여 줄 것이 사라진다** —
H-1 이 세운 패턴이다. SelectionBox 는 md 자신의 분류(부분 스펙, md:604)를 인용해
재현임을 밝혔다. **md 가 침묵하는 것을 "md 에 없다" 고 쓰지 않는다** — H-1 의 Drawer 노트가
그 실수를 했고, 여기서는 md 가 유보를 _명시_ 했으므로 인용이 성립한다.

## H-2b. krds — 13개 중 12개가 md 와 일치한다

카드 3종은 md:309·313·317 과 문자 그대로 같다. `좌측 컬러 보더 미사용` 이라는 부재 주장도
md:319·478 이 명시적으로 뒷받침한다 — **부재 주장이라고 자동으로 결함인 것은 아니다.**
리드는 md:22 와 같은 문장이고, 나머지 캡션도 md:26·169·260·305·327·339·391·415·496 에
대응한다.

정정은 1건 — `5단계 stepper` → `5단계 step-indicator`. md 는 이 컴포넌트를
`step-indicator` 로 발행하고(md:381) 5단계 흐름도 `{component.step-indicator}` 로
참조한다(md:450). `stepper` 는 md 에 0건이다. H-1 의 `DropdownItemSelect` 와 같은 부류다.

### 토큰명은 고치고 로컬 클래스명은 두는 경계

krds 프리뷰의 CSS 클래스 `.stepper` 는 **그대로 뒀다.** socar 에서
`--sf-information-weak` 를 바꾼 것과 다르다 — **디자인 토큰 이름은 이 카탈로그가 발행하는
산출물이라 소비자가 복제하지만, 로컬 CSS 클래스명은 프리뷰 내부 구현**이다. 판단이
갈리면 _그 이름이 카탈로그 밖으로 나가는가_ 를 묻는다.

### 목업 화면 안 카피는 대상이 아니다

krds 의 16개(`본인 인증 시 등록된 이름이 자동 입력됩니다` · 서비스 타일 `tile-desc` 4개
등)는 표시 데이터다. 이 계열의 표시 데이터 처리 방침은 D-1 에서 정해졌다 — **제거·익명화가
아니라 더미 라벨링**. H-3 이 재논의하지 않도록 여기 적는다.
