# 그리팅 프리뷰 마크업 정리 — 빈 카드 제거 + 클래스명 정합

H-4(PR #232, squash `5f927f1`)가 그리팅 프리뷰 **산문** 감사를 끝내면서 산문이 아닌 관찰
세 가지를 "범위 밖" 으로 넘겼다. 산문 정정 PR 에서 마크업을 바꾸면 회귀 원인이 섞이기
때문이었다. 그 셋을 여기서 처리한다 — **둘은 고쳤고 하나는 조사 결과 결함이 아니었다.**

착수 계기는 저장소 소유자의 질문이었다 — *"라이브 프리뷰에서 사용하지 않게 된 브랜드
로고 파트를 정리해야 하지 않을까?"*

## 로고 *자산* 은 이미 깨끗했다

질문에 답하기 위해 먼저 자산을 셌다. `public/logos/` 에 `greeting.svg` 하나뿐이고 양
프리뷰에서 **3 회씩** 실제로 참조된다 — 히어로 · ATS 셸 사이드바 · 푸터. 고아 파일
0 건이며 묶음 B(#206)가 그때 정리했다. frontmatter `logo` 도 같은 파일을 가리킨다.

**즉 남은 것은 자산이 아니라 자산 없이 남은 카드였다.** 질문의 방향은 맞았고 대상이
한 겹 달랐다.

## ① `Doodlin wordmark` 카드 — 제거

렌더되는 것이 회색 박스 하나뿐이었다:

```html
<div class="row"><span class="slot">두들린 워드마크 — 자산 미수록</span></div>
```

시각적으로 시연하는 것이 없고, 그 카드가 말하는 "두들린은 회사, 그리팅은 제품" 은
같은 그룹에서 **네 번 반복**된다 — 그룹 리드 · 카드 노트 · Naming 부제 · Naming 본문.
고유 기여는 빈 박스뿐이었다.

**카드를 지워도 정보 손실이 없다** — 그룹 리드가 "이 프리뷰가 싣는 브랜드 자산은
그리팅 심볼 벡터 하나다" 를 그대로 싣는다.

바로 옆 `Brand imagery` 카드도 빈 슬롯을 쓰지만 **성격이 다르다** — 마케팅 표면 ↔ 제품
UI 를 대비시켜 md 의 "제품 UI 는 이미지를 한 조각도 들여오지 않는다" 를 실제로 시연한다.
빈 슬롯이라는 형태가 같다고 같은 판정을 하면 안 된다.

카드가 줄었으므로 **카운터 두 곳을 함께 내렸다** — `grp-ct` `3장` → `2장`, 상단
`Doodlin UI · 35 cards` → `34 cards`. 검산 `3+5+19+1+4+1+2 = 35` → `2+5+19+1+4+1+2 = 34`.

## ② `.drawer*` → `.panel*` — 리네임

H-4 가 카드 제목을 `Drawer` → `Side panel` 로 바꿨지만(md 전문에 `Drawer` 0 건) 셀렉터는
그대로였다. 파일당 11 곳(CSS 주석 1 · CSS 규칙 6 · 마크업 4)을 옮겼다.

**`.side` 를 쓰지 않았다** — `.side-lbl` 이 ATS 셸 **사이드바** 섹션 라벨로 이미 있어 의미가
겹친다. `.panel` 은 이 파일에서 CSS 규칙 0 · class 사용 0 으로 비어 있었다.

**`line-design-system` 프리뷰도 `class="drawer"` 를 쓰지만 건드리지 않았다.** 그 슬러그는
아직 산문 감사를 받지 않았고 그쪽 md 에 `Drawer` 가 있는지 확인되지 않았다 — **이름이
같다는 이유로 다른 슬러그를 함께 고치면 근거 없이 범위를 넓히는 것이다.**

## ③ `.rail` — 조사 결과 결함이 아니다. 종결한다

H-3 이 "`.rail` 이 어느 서술도 시연하지 않는다" 로, H-4 가 "높이가 28px 이 아니라 32px 이라
`Tabs` 인지 `MenuItem` 인지 모호하다" 로 넘긴 관찰인데 **둘 다 성립하지 않는다.**

- `.rail`(light:420)에 border-radius 가 없는 것은 **컨테이너라서** 정상이다. radius 를 갖는
  것은 `.rail-item`(422)이고 `--r6` 이다.
- 32px 은 `Tabs` 와 어긋나지 않는다 — **이 레일은 `Tabs` 가 아니라 `TabsRail`** 이고,
  md `### tabs-rail` 은 "`Tabs`/`TabItem` 과 **별개의 두 번째 탭 계열**" 이라 명시하며 치수를
  싣지 않는다. 같은 카드의 **수평 탭 데모 `.tab`(light:414)은 실제로 28px** 이고, 노트의
  "Tabs 아이템 28px" 은 그쪽을 정확히 서술한다.

**H-4 스펙의 "모호하다" 는 서술이 두 컴포넌트를 겹쳐 읽은 것이다.** md 가 별개라고 못 박은
둘을 하나로 봤다. 고쳤다면 md 가 치수를 싣지 않는 컴포넌트에 값을 부여하게 된다 —
이 계열이 내내 지우려던 유형이다.

**교훈: 관찰을 이월할 때 근거까지 이월되지는 않는다.** H-3 이 남긴 한 줄이 H-4 에서
한 겹 더 얹히며 결론이 강해졌고, 실제로 파일을 열기 전까지 아무도 되짚지 않았다.
