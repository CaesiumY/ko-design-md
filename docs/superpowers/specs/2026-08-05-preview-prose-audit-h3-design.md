## 계수가 네 번째로 작았다

H-2 스펙이 인계한 greeting 수치는 `note` **42(후보)** 였고, H-3 착수 시점의 이해는
"42 중 36 미감사" 였다. 표면을 전수로 뽑으니 **93개**다.

| 서술 표면                       | 개수 |
| ------------------------------- | ---- |
| `p.note`                        | 42   |
| `.card-hd` (제목 + `<em>` 부제) | 44   |
| `.grp-hd` (그룹 리드)           | 7    |

**H-1 의 172(단위 오류) · H-2 의 krds 4→30 · 이번 36→93 — 세 번 연속으로 계수가 작았다.**
공통 원인은 매번 **한 종류의 표면만 세고 나머지를 안 본 것**이다. 그래서 이번에는 계획
단계에서 클래스를 전수로 뽑았고, 그러고도 **네 번째 표면을 놓쳤다**(아래 참조).

**`note` 41/42 불일치는 마크업 문제가 아니었다** — 42개 전부 `class="note"` 이고, 41 은
요소 스캔의 `12자 미만` 필터에 걸린 짧은 노트 하나 때문이었다.

**목업 콘텐츠는 대상이 아니다**(D-1 결정) — `qa` 5 · `ap-row` 4 · `rec` 4 ·
`callout-inline` 3 등.

### 검토했으나 결함이 아닌 것 (H-4 가 재논의하지 않도록)

- **`Dark mirror` 부제의 `resolved under [data-theme=dark]`.** 구현은 `.pane-d` 가
  `--p-*` 를 직접 재정의하지 `[data-theme=dark]` 셀렉터를 쓰지 않는다. 그러나 그 값
  (`oklch(1.000 0.000 0 / 0.85)` 등)이 **md:183 의 다크 resolution 과 정확히 일치**하므로,
  기제가 아니라 _값이 무엇으로 해석되는지_ 를 말하는 문장으로 성립한다. 무변경.
- **Spacing 노트의 `dist/constants/`.** md:528 의 벤더 중립 Don't 는 내부 경로 이름을
  **생성하는 제품 UI** 에 넣지 말라는 것이고, 여기는 프로비넌스를 설명하는 카탈로그의
  서술 층이다(H-2 가 세운 경계). md:293 자신도 같은 경로를 쓴다. 무변경.

## 정정 1건 — `radius8` 용도 매핑

md:331-338 의 실측 적용 표는 **4px · 6px · 10px · 100% 네 행뿐이고 8px 행이 없다.**
md 가 `radius8` 의 용도로 적는 것은 **카드**다 — md:345 `카드는 {rounded.radius8} + 1px
보더로 정의되며`. md:467-469 의 `tabs-rail` 에는 radius 지정이 아예 없다.

**프리뷰 자신의 CSS 도 그 산문을 반박하고 있었다.**

```
var(--r8) 사용:  .card · .ap-card · .pane · .fbox · .modal · .shell   ← md:345 와 일치
.rail-item:      var(--r6)
.rail:           border-radius 없음
```

즉 `8px Tabs rail(lg)` 은 **md 에도 없고 렌더에도 없었다.** md 대조만 했으면 "md 에 없다"
까지만 나왔을 텐데, 렌더를 함께 보니 **자기반박**이라는 더 강한 판정이 나왔다.

### 같은 결함이 세 표면에 있었다 — 그중 하나는 목록에 없었다

| 표면                      | before              | after      |
| ------------------------- | ------------------- | ---------- |
| 카드 부제 `.card-hd em`   | `8 tabs rail`       | `8 cards`  |
| **데모 칩 라벨 `<span>`** | `8 · Tabs rail`     | `8 · Card` |
| 노트 `p.note`             | `8px Tabs rail(lg)` | `8px 카드` |

**칩 라벨은 이 PR 이 정한 감사 표면 목록(`note` · `card-hd` · `grp-hd`)에 없었다.**
원문 grep 으로만 걸렸다. H-2 가 socar `.meta-chip` 과 krds `.row-label` 을 빠뜨린 것과
같은 형태이고, **계획 단계에서 클래스를 전수로 뽑았는데도 재발했다.**

**교훈은 "칩 라벨도 목록에 넣어라" 가 아니다** — 그건 다음 형태에서 또 뚫린다.
**고칠 문자열이 정해지면 그 문자열을 파일 전체에서 grep 해 몇 군데 있는지부터 센다.**
표면 목록은 _무엇을 읽을지_ 를 정하는 데 쓰고, _무엇을 고칠지_ 는 문자열로 확인한다.

03 Components 그룹의 `TabsRail 은 Tabs 와 별개인 두 번째 탭 계열이고` 는 md:469 와
일치하므로 그대로 뒀다(그 그룹은 이번 범위 밖).
