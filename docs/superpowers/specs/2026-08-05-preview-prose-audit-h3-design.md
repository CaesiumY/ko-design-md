## 철회했다가 md 를 고쳐 되돌린 정정 — `radius8` 용도 매핑

> **이 절의 초판은 거짓 근거 위에 있었고, 리뷰가 잡아 철회했다. 무엇이 왜 틀렸는지가
> 다음 사람에게 필요하므로 지우지 않고 남긴다.**

초판은 `8px Tabs rail(lg)` 을 무출처로 판정하고 `8px 카드` 로 바꿨다. 근거로 든 세
자리(md:334-339 실측 표에 8px 행 없음 · md:345 가 radius8 을 카드에 배정 · md:467-469
`tabs-rail` 에 radius 지정 없음)는 **전부 사실이지만**, 정작 그 표 **바로 아래 문단**을
안 봤다.

```
md:341 …위 표는 전부 컴포넌트 실측이며, 용도 매핑을 만들어 인용하지 말 것.
       배포 번들에서도 `radius8`은 Tabs 계열 컨테이너(lg)에서만,
       `radius10`은 Badge에서만 쓰인다 [src:2][src:4].
```

**프리뷰의 `(lg)` 괄호까지 md:341 에서 온 것이었다.** 즉 md 가 지지하는 서술을 거짓
부재 판정으로 지우고 다른 서술로 바꾼 것이고, 대체 문구 `8px 카드` 는 md:341 이 명시적
으로 금지하는 **`용도 매핑을 만들어 인용`** 에 해당한다. md 문구
(`Tabs 계열 컨테이너(lg)`)로 되돌렸다 — 원래 표기 `Tabs rail` 보다 md 에 가깝다.

### 근본 원인 — 잘린 출력으로 판단했다

`sed -n '341p' | cut -c1-230` 으로 읽었고, 잘려나간 뒷부분이 판정을 뒤집는 내용이었다.
**이 PR 이 앞 커밋에서 세운 교훈("고칠 문자열을 파일 전체에서 grep 해라")도 이걸 못
잡는다** — 문제는 검색 범위가 아니라 출력 절단이다.

**md 한 줄이 화면 폭을 넘으면 `fold` 로 전문을 보고 나서 판정한다.** 부재 판정은 특히
그렇다 — md 는 한 문단이 한 줄인 형식이라 `cut` 이 문단 중간을 자른다.

### 해소 — 진짜 결함은 md 에 있었다

초판 판정(`8px 카드`)은 **실질에서 맞았고 근거가 틀렸다.** md 를 `cut` 으로 잘라 읽고
"md 에 없다" 고 단정했는데, 실제로는 **md 에 있었고 그 있는 쪽이 틀렸다.**

`## Rounded` 절이 `radius8` 의 용도를 세 곳에서 다르게 적고 있었다.

| 자리               | 서술                                                            | 인용             |
| ------------------ | --------------------------------------------------------------- | ---------------- |
| md:334-339 실측 표 | **8px 행이 없다**                                               | `[src:1]`        |
| md:341             | `배포 번들에서도 radius8은 Tabs 계열 컨테이너(lg)에서만 쓰인다` | `[src:2][src:4]` |
| md:345             | `카드는 {rounded.radius8} + 1px 보더로 정의되며`                | `[src:1]`        |

**md:341 의 인용이 주장을 뒷받침하지 못한다.** `[src:2]` 는 npm 패키지 페이지,
`[src:4]` 는 레지스트리 JSON 으로 둘 다 **`dist/constants/` 디렉터리의 존재**를
뒷받침하는 메타데이터 소스다(md:320 이 정확히 그 용도로 인용한다). 번들 CSS 실측은
이 문서에서 `[src:1]`(Storybook)이 담당한다. CLAUDE.md 의 **"인용은 존재가 아니라
내용 일치"** 위반이다.

**그 문단은 자기 규칙도 어긴다** — 같은 문단이 `용도 매핑을 만들어 인용하지 말 것`
이라 적어 놓고 바로 다음 문장에서 용도 매핑을 만든다.

**조치** — 인용이 뒷받침 못 하는 문장을 걷어내고, 실측 표에 `8px | 카드` 행을 넣었다
(근거는 md 자신의 `## Elevation & Depth` `[src:1]`). `radius10` · Badge 는 이미 표에
있어 그 문장이 더하던 정보가 아니었다. `## Rounded` 첫머리에 감사 메모를 남기고
`last_updated` 를 `2026-08-05` 로 올렸다. 프리뷰 세 표면도 `8px 카드` 계열로 맞췄다.

**이 PR 이 `services/*.md` 를 건드리는 첫 H 묶음이다.** 계획은 _"프리뷰가 맞고 md 가
틀렸다가 나오면 멈추고 보고한다"_ 로 적었고, 실제로 그 지점에서 멈춰 승인을 받고
진행했다. `check:last-updated` 는 `1 changed file(s) — 0 issue(s)` 로 통과한다.

**남은 관찰 — 프리뷰 `.rail` 은 어느 서술도 시연하지 않는다.** `.rail` 컨테이너에는
border-radius 가 없고 `.rail-item` 만 `--r6`(md:465 `아이템 … radius6` 과 일치)다.
md 가 이제 8px 를 카드에 배정하므로 모순은 아니지만, **레일 데모가 radius 축에서
보여 주는 것이 없다**는 점은 H-4(03 Components)가 볼 자리다.

## 리뷰가 잡은 것 — 네 번째 표면 클래스

**`span.u` 가 감사 표면 목록에 없었다.** 05 Shape 의 Motion 카드가
`<span class="u">ToggleSwitch 트랙 · Drawer</span>` 를 렌더하는데, md 에 `Drawer` 는
**0건**이고 md:364 는 `duration-slow: 0.3s # ToggleSwitch 트랙` 만 적는다.

**H-1 이 이미 철회한 주장이 반대 방향으로 살아 있었다.** 커밋 `6420c0a` 이 03
Components 의 Drawer 카드 노트에서 `큰 상태 변화라 0.3s 듀레이션 자리다` 를 지웠는데,
05 Shape 의 Motion 카드는 같은 매핑을 `0.3s → Drawer` 방향으로 계속 말하고 있었다.

이로써 **감사 표면 목록이 네 번 불완전했다** — H-2 의 socar `.meta-chip` · krds
`.row-label` · 이 PR 의 데모 칩 `<span>` · `span.u`. 계획 단계에서 클래스를 전수로
뽑았는데도 재발했다. `span.u` 는 **고칠 문자열이 특정되지 않은 표면**이라 앞 커밋의
